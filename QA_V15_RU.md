# «Игровая галактика» v15 — техническая доработка и подробный QA

**Статус: архитектурные исправления выполнены; полный браузерный QA НЕ завершён. Релиз не сертифицирован как FULL_QA_READY.** Название ZIP сохранено по запросу пользователя; оно не означает, что 48 мобильных сценариев прошли проверку.

Исходник — приложенный v14; все 16 исходных игровых движков сохранены. Проект не создавался заново. Главный источник требований — приложенный «Вставленный Markdown.md» (отдельного TXT среди двух вложений не было). Копия требований включена в сборку.

## 1. Ограничение, которое помешало завершить требуемый QA

Playwright установлен в окружении, но браузерного бинарника изначально не было. Две стандартные установки Chromium вернули вместо ZIP короткий HTML-ответ. Бинарник Chromium 153 получен через пакет @sparticuz/chromium и распакован в разрешённый рабочий каталог. Попытки запуска завершились **SIGTRAP до создания страницы**, в том числе с настройками serverless-пакета. Полный лог сохранён в `qa/results/browser-launch-error.txt`.

Облачный Chrome также проверен: открытие локального HTTP-сервера отклонено с `net::ERR_BLOCKED_BY_CLIENT`. Поэтому не получены настоящие DevTools console logs, мобильные скриншоты и измерения layout. Публикация на Netlify/другом хостинге не выполнена. DOM-runtime ниже не заменяет Chromium, Android или end-to-end QA.

## 2. Найденные причины и выполненные изменения

1. **Самозапускающийся MutationObserver v13.** `cleanup()` всегда присваивал заголовку `textContent`, а observer отслеживал `childList` всего документа. Даже запись того же текста создаёт новую DOM-мутацию и снова вызывает cleanup. Оригинальный скрипт воспроизведён в изолированном jsdom worker с путём шахмат: 4128 вызовов за 1500 мс, контрольный timer не выполнился. Это воспроизведение механизма блокировки DOM, а не воспроизведение страницы в DevTools. В v15 этот observer полностью удалён.
2. **Горизонтальная modal из v14.** У ряда игр содержимое настроек являлось прямыми детьми `#setup/#aiSetup`. Общий CSS задавал overlay `display:flex` с горизонтальным направлением и каждому ребёнку ширину окна. Обобщение считало каждый заголовок, label и группу кнопок отдельной карточкой. Теперь у каждого такого блока есть ровно один `.modal-card`; overlay управляет позиционированием, карточка — вертикальным потоком. Закрытый modal исключён из layout. Сохранены исходные handlers выбора и старта партии.
3. **Готовность iframe.** Убрано скрытие loading по одному событию `load`. Игра явно отмечает завершённую инициализацию движка и подтверждает готовность после загрузки своей заставки. Ошибки JS, rejected promises и незагруженные scripts передаются платформе. Без подтверждения за 15 секунд показывается ошибка с «Повторить» и возвратом в каталог, а не поддельная готовность. Проверяются origin, source, game ID и номер launch; устаревшие ответы retry игнорируются.
4. **Единый shell вместо наслоения.** Подключения, файлы и обработчики общих v12/v13/v14 compatibility-слоёв удалены, как и старые injected portrait/final-polish patches. Оставлены игровые engines, один `game-shell.css`, один `game-shell.js` и `game-lifecycle.js`. Каталог имеет один собранный stylesheet; его исходный дизайн сохранён.
5. **«Уголки»: fatal exception до кнопки старта.** `buildMini()` обращался к `#miniGrid`, которого уже не было в заменённой заставке. Отсутствующий декоративный элемент теперь пропускается; инициализация игровых handlers не прерывается.
6. **Размеры и аватары.** Для шахмат/шашек удалены JS-вычисления абсолютных offsets, конфликтовавшие с grid. Размер доски определяется доступной шириной и отступами координат без прежнего минимального 260/270 px. У Реверси убран JS-fit, который учитывал старое наложение аватаров. Общие правила размещают аватары вне поля; исправлен modal markup и ограничения ширины. Эти изменения проверены по исходникам и DOM, но фактическая геометрия на телефоне остаётся непроверенной.
7. **Навигация.** Удалены конкурирующие генераторы кнопок; у каждой игры одна `#allGames`. Кнопка отправляет платформе exit, при самостоятельном открытии ведёт в `../../index.html#games`. «В начало» у нард исправлена со splash на меню текущей игры. В каталоге кликабельна вся карточка.
8. **Асинхронные игровые сессии.** Timeout/interval движков теперь принадлежат сессии GameLifecycle. Новая партия или выход в меню отменяют старые callbacks: ожидающий ход AI/анимация не должен изменять новую партию. Проверена отмена timeout и interval отдельным тестом.
9. **Рекорды.** Сохранены прежние localStorage keys и модель `youthGalaxy.records.v2`. Добавлены монотонные `getBest/updateBest`; 2048 сохраняет best сразу при увеличении счёта и читает его в новой партии. Каталог учитывает этот best. Регистрация не добавлялась; будущий backend adapter сохранён. Ни один обработчик новой партии не очищает legacy-рекорды в выполненных тестах.
10. **Ресурсы.** Использованы исходные 16 тематических заставок v14 и правильные общие PNG персонажей. Пустые hero holders нард получили изображения в HTML. Персонажи из старого v14 observer больше не принудительно подменяются после выбора героя. Большие base64 изображения вынесены в дедуплицированные файлы. Пути icons/splashes стали стабильными без номера версии. Удалены 162 невостребованных изображения/старых дубля, прежние отчёты и скриншоты. Старые logo images убраны из HTML, визуальные logo slots скрыты. Сохранены нужные игровые ресурсы.

В jsdom для исполнения движков подменены AudioContext, matchMedia, ResizeObserver и scrollIntoView; он не вычисляет layout и не воспроизводит touch. Настоящие handlers вызываются DOM-click/keyboard событиями, проверяются изменения доски/счётчиков, а не только открытие экранов. Это проверка логики и DOM-интеграции, а не браузерный end-to-end тест.

В 16 базовых тестах новая партия сохраняет существующий legacy-рекорд. Где естественный рекорд ещё не заработан, перед проверкой используется явно обозначенный fixture. Зеркалирование в schema v2 проверено. Реальная browser persistence после reload, перезапуска и обновления приложения не проверена. Мемори отдельно завершена с сохранением через штатное окно имени.

## 7. Воспроизводимость и состав сборки

- `qa/dom-qa.cjs`: выполненные интеграционные действия для 16 игр.
- `qa/variant-qa.cjs`: выполненные 13 дополнительных режимов/побед.
- `qa/protocol-qa.cjs`: выполненные protocol/storage/scheduler тесты; сообщения ready/error в них synthetic.
- `qa/browser-qa.cjs`: подготовленный native Chromium runner на 48 сценариев. Проверяет реальные клики, свайпы 2048, console/page errors, HTTP errors, viewport bounds, перекрытия, menu/new/exit. В этой среде остановился на launch. Он также не является полным набором всех terminal-state правил из требований.
- `qa/results/*.json`: фактические результаты, отдельный файл BLOCKED-матрицы и launch log.
- `static-qa-results.json`, `image-qa-results.json`, `pruned-assets.json`: аудит и список удалённых assets.
- `REQUIREMENTS_RU.md`: исходные требования пользователя.

Запуск обычного статического сайта: `python3 -m http.server 8080` из каталога сборки, открыть `http://localhost:8080/`. В Netlify publish directory должна быть папка с `index.html`, а не внешняя папка архивного файла. Backend/build step не требуется. Все runtime ресурсы находятся внутри архива; Google Fonts dependencies удалены.

Повтор QA в нормальном окружении: перейти в `qa`, выполнить `npm install`, `npx playwright install chromium`, затем `npm run dom`, `npm run variants`, `npm run protocol`, `npm run browser`. Результаты пишутся в `qa/results`. Native runner использует отдельные browser contexts для сценариев и не меняет реальный пользовательский storage. После его успешного запуска ещё требуется завершить перечисленные выше terminal-state и Android checks.

## 8. Решение о готовности

**Полная готовность не подтверждена.** Архитектурные дефекты и дополнительные инициализационные ошибки исправлены, логические/DOM проверки проходят. Мобильная адаптация изменена, но не получила требуемую визуальную и функциональную браузерную проверку. Архив нельзя честно назвать прошедшим полный QA; оставшиеся BLOCKED/NOT_RUN пункты перечислены явно.
