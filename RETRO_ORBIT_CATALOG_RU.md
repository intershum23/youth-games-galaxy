# Ретро-орбита — каталог и аудит механик

Дата: 5 октября 2026. База: [intershum23/youth-games-galaxy](https://github.com/intershum23/youth-games-galaxy), main v16.14.1, SHA `b935c3eb6fffd361f86c8a8b0a80c3b0b46ea4bb`. В прикреплённом промпте имя владельца `intersum23` содержит опечатку. Проверено по фактическому репозиторию: 17 игр, включая Капсулы.

В ходе работы пользователь расширил задание: «капсулы тоже переделай. не просто проектируй, а делай игры тоже». Поэтому этот этап включает доработку Капсул и первую новую игру Космическая почта. Нереализованные кандидаты ниже остаются проектами, а не прошедшими browser QA играми. В v16.15 были реализованы 18 игр. Продолжение v16.16 добавляет Радиомаяк — теперь 19 реальных игр.

## Общий принцип

Ретро относится к механике фиксированных позиций и короткой сессии, а не к визуальному копированию LCD-корпуса или чужих персонажей. Космос, неон, Montserrat и Unbounded, собственные уровни/звуки; эталонный рыже-белый взрослый корги и белый кот с круглыми оранжевыми очками. Каждая новая игра получает свои icon, active icon, title-art, splash, необходимые реальные игровые позы и объекты. Состояния, HUD и кнопки выбираются по правилам конкретной игры. Нет обязательного фиктивного соперника, прыжка, жизней или ИИ для всех жанров.

Все параметры и режимы будущих игр ниже — проектные предложения. Уникальность оценена по основному действию, решению, ресурсам и условию неудачи; окончательное ощущение сходства нужно перепроверить на прототипе. Смена темы не считается новой механикой.

## 20 кандидатов

### 1. Капсулы

Статус аудита: **УНИКАЛЬНАЯ МЕХАНИКА**.

| Поле | Проектное решение |
|---|---|
| Название | Капсулы |
| Короткая идея | Перехват энергии на четырёх дорожках. |
| Core gameplay loop | Увидеть ближайшее прибытие → занять одну из четырёх позиций → автоматически принять капсулу → сменить позицию. |
| Управление на телефоне | Четыре кнопки либо четыре зоны поля. |
| Управление на ПК | Q/E/Z/C; NumPad 7/9/1/3; Space — пауза. |
| Цель | Рекорд до трёх пропусков. |
| Победа / поражение | Обычной победы нет; третий пропуск завершает раунд. |
| Режимы | Существующие GAME A / GAME B / TURBO. |
| Рост сложности | Больше параллельных объектов, более короткий полёт и интервал; ограничение несовместимых прибытий. |
| Отличие от Капсул | Базовая существующая механика, повторять её нельзя. |
| Отличие от остальных кандидатов | Единственная игра с автоматическим перехватом по удерживаемой позиции. |
| Сложность реализации | средняя |
| Нужные изображения / позы | Существующие icon/active/title/splash и два отдельных 2×2 листа направленных поз. В v16.15 icon/active/title/splash сохранены; игровые листы поз обновлены, движок и layout доработаны. |

|---|---|

| Отличие от Капсул | Только если есть обязательное решение о расходе/окне щита; вариант «четыре сигнала → четыре кнопки» слишком похож. |
| Отличие от остальных кандидатов | От активного магнита отличается защитой сразу нескольких секторов и выбором распределения заряда. |
| Сложность реализации | средняя |
| Нужные изображения / позы | Общий комплект серии; оператор, зарядка/активация/перегрев щита; три вида угроз с явной телеграфией. |

### 6. Космическая почта

Статус аудита: **УНИКАЛЬНАЯ МЕХАНИКА**.

|---|---|
| Название | Космическая почта |

| Управление на телефоне | Три адреса плюс отдельная кнопка отправки. |

| Нужные изображения / позы | Новые icon/active/splash сгенерированы и установлены; прозрачный PNG-title экспортирован из Unbounded; существующие портреты операторов. |

## Дальнейшая реализация

Перед следующей игрой: получить свежий main → проверить наличие более нового HEAD → сравнить core loop со всеми уже добавленными играми → уточнить паспорт → SPEC → необходимые ресурсы → реальный движок → manifest/generated catalog → реальные действия и конечные состояния → проверка всей платформы → GitHub и опубликованная версия. Не менять framework, не возвращать compatibility-слои v12/v13/v14, не пересобирать платформу с нуля.

Для ретро-игр применяется `cat: retro`. Существующие логические/настольные фильтры остаются; не создаём заранее 18 пустых разделов. Генератор каталога обязан не только писать файл, но и выполнять созданный JavaScript в проверочном контексте и сверять число игр.

Каждая новая SPEC задаёт собственные кнопки, время, ресурсы, цель, конечные состояния и UI. Это позволяет добавлять разные механики, а не клонировать один движок. Общая оболочка владеет загрузкой, экранами, типографикой и материалом; движок владеет правилами, состоянием, кадрами и результатом.
